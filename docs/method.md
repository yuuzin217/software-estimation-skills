# 採用した見積もり手法

## 採用

- WBSによる作業分解。要件IDで追跡する
- ボトムアップの三点見積もり
- PERT期待値 `(O + 4M + P) / 6`
- 条件が一致するときだけの外部ベンチマーク照合
- 説明できる類似度と、同じ規模指標による実績の按分

計算はPython標準ライブラリの十進演算だけが行う。LLMは要件の分解と、三点や前提の起草を担当する。

## 採用しなかったもの

- COCOMO。規模とコストドライバが揃わないと機能せず、係数を本件向けに作ると根拠の捏造になる
- ファンクションポイントの計測そのもの。計測手順は入力側の作業とし、FP値が明示されたときだけIPAのFP生産性を照合候補にする
- IPA資料の回帰式。同書が、個別プロジェクトへの直接適用は適当でないと説明している
- CoBRA法。有識者合意による変動要因モデルであり、初期版の自動計算には載せない
- モンテカルロシミュレーションや機械学習。件数が少ない段階では説明より精度が高く見える

## 実績が無いとき

外部の生産性が使えなくても見積もりを止めない。WBSと、暫定であることを明示した三点で範囲を出す。統計が無い部分を、それらしい標準人日で埋めない。

## 実績があるとき

データの品質、工程の対応、規模指標の一致を優先する。類似しない実績は捨てるか、不採用理由とともに残し、補正係数では採用しない。3件未満は主方式にしない。10件未満は暫定のままである。

新規・改修などの `project_scope` が異なる実績は、類似度の点数にかかわらず按分しない。有効実績の最小・最大規模から上下2倍を超える外挿も行わず、cold-startへ切り替える。この倍率は本ツール独自の安全策であり、IPAなどの公式基準ではない。

## 網羅性と出力

cold-startでは機能要件・非機能要件のそれぞれに算定可能なWBSがあり、未算定WBSが無い場合だけ全体見積もりとする。未対応要件または未算定WBSがある場合、算定できた工数は部分見積もりとして表示し、全体の費用・期間は出さない。historicalは案件全体を対象とし、WBSは照合用として別に状態を示す。

計算結果のJSONを正本とし、MarkdownとCSVは同じ結果から出力する。出力側で工数を再計算しない。
