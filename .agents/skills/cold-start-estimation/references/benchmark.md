# 外部ベンチマーク

公開統計は、適合するときの照合に限る。WBSの計画工数を置き換えない。統計が無くても、WBSと明示した仮定で暫定見積もりを作る。

## 照合してよい条件

すべて満たすときだけ `benchmark` を埋める。

- `catalog_id` が `python -m estimator list-benchmarks` にあり、`calculable` が true
- 開発種別が `new` または `enhancement` で、資料の層別と一致する
- 測定単位が `sloc` または `fp` で、本件の規模と同じ定義である
- `confirmed_phases` が資料の開発5工程と一致する。内訳は基本設計、詳細設計、実装、結合テスト、総合テスト（ベンダ確認）
- 要件整理、移行、運用引き継ぎなど範囲外の工数を、その比較へ混ぜない
- 母集団がエンタプライズ系の受託開発であり、本件の技術や契約と違う点を `population_note` に書く
- `acknowledge_population_limits` を true にするのは、上記を確認したときだけ

標本数が少ないFP生産性は、計算されても参考値である。計画工数に採用しない。

## 照合しないもの

- プロジェクト全体の中央工数（7395人時）や中央工期（10.1カ月）。母集団のプロファイルであり、本件の目標値ではない
- SLOCや調整前FPが無い案件への無理な換算
- 資料の回帰式。目録に無く、IPA自身が個別見積もりへの直接適用は適当でないと説明している
- クラウド開発やAI支援開発への無条件の流用

条件が一つでも欠けるときは換算しない。欠ける理由を依頼に残すと、出力の不採用理由になる。空の標準値では埋めない。

出典と制約の詳細はリポジトリの `docs/references.md`。
