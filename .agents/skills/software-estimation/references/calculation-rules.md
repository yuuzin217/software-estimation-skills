# 計算規則

実装の正本は `estimator` パッケージ。この文書とスクリプトが矛盾する場合は、テストされているスクリプトを優先し、文書を直す。

## 工数

基本単位は人日（`person_day`）。人時（`person_hour`）も扱える。1件の見積もり内で単位を混ぜない。

人時と人日を変換するときは `hours_per_person_day` が必須である。8時間や160時間を補わない。IPA資料の「1人月＝160時間」は、同資料が人時を人月表示するときの代用であり、本ツールの人日換算には使わない。

## 三点見積もり

各算定可能項目について、楽観値 O、最頻値 M、悲観値 P を持つ。

- O >= 0
- O <= M <= P
- 有限の整数、または十進文字列

PERT期待値は次のとおり。

```text
E = (O + 4M + P) / 6
```

Eは保証値ではない。Pは信頼区間の上限ではない。O、M、Pの合計それぞれのPERTは、項目ごとのEの合計と一致する。

## 根拠の区分

| 区分 | 意味 |
| --- | --- |
| SOURCE | 検証できる外部資料。目録のIDか、題名・発行元・年・https URL |
| HISTORICAL | 入力された開発実績。実績IDが必須 |
| ASSUMPTION | 明示した仮定 |
| AI_ESTIMATE | AIの暫定推定。`provisional: true` が必須。出典IDを付けない |

目録に無い値を SOURCE にしない。

## 丸め

工数と金額は、丸める前の十進数で合計し、最後に一度だけ小数第2位へ丸める。方式は ROUND_HALF_UP。項目を先に丸めてから足さない。

## 網羅性

機能要件と非機能要件の各IDが、少なくとも1つの算定可能WBSへ結び付いていることを確認する。未対応要件または未算定WBSが1つでもあれば、cold-startの網羅性は `partial` であり、算定済み項目の工数は部分見積もりとする。未算定項目を0として計上せず、対象全体の費用・期間を算出しない。

historicalを主方式にする場合は案件全体の規模按分見積もりを使う。WBSは照合用であり、その網羅性によってhistoricalの主見積もりを制限しない。照合用WBSの網羅性や未算定作業は別途表示する。

## 出力形式

計算結果オブジェクトを `estimate.json` として保存し、そこからMarkdownとCSVを作る。JSONの `*_exact` は丸め前の十進値、MarkdownとCSVは同じ2桁表示値を使う。CSVのクォートはフィールド構造を保つために使い、Excel数式対策として危険な先頭文字列へアポストロフィを付ける。

## 費用

```text
労務費 = 計画工数 × 単価
合計 = 労務費 + 経費
```

単価が無いときは費用を出さない。経費だけを開発費にしない。単価の根拠が `AI_ESTIMATE` の依頼は拒否する。利用者が指定した単価は `ASSUMPTION` とし、市場相場の調査結果であるように書かない。

## 開発期間

人数と稼働率の両方があるときだけ、次の下限を出す。

```text
経過日数の下限 = 人日の計画工数 / (人数 × 稼働率)
```

これはクリティカルパスではなく、確定期間でもない。レビュー待ち、外部依存、非稼働日を含まない。暦日へ広げる場合だけ `calendar_factor`（1以上）と仮定文を指定する。係数が無いときに週末や祝日を補わない。

人時のままでは、`hours_per_person_day` が無い限り期間へ換算しない。

## 予備工数

三点見積もりに含まれる不確実性を、予備として重ねない。予備を置く場合は、独立した理由と、三点に含めていないリスクIDが必要である。historical が主方式のとき、WBS向け予備は加算しない。

割合項目は `derivation.type = percent_of` のときだけ計算する。既定の管理係数は無い。基準WBSが重なる割合項目は警告する。

## 外部ベンチマーク

条件がすべて揃うときだけ、人時の照合幅を計算する。計画工数には加算も置換もしない。

- 目録IDが実在し、工数換算できる項目である
- 開発種別、測定単位、開発5工程の一覧が資料と一致する
- 規模が資料の規模帯に入る
- 母集団の限界を確認した旨と、比較する理由がある

標本数が30未満の項目は参考値であり、計画工数にしない。母集団の中央工数や中央工期は、個別案件の目標値にしない。

回帰式は目録に入れておらず、計算もしない。

## 再現性

同じ依頼JSONは同じ結果になる。見積日は入力で与え、計算時の現在日付では補わない。
