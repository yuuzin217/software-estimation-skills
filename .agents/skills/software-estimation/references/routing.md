# 方式選択

数値の採用可否は `python -m estimator` が決める。エージェントは判定理由を書き換えない。

## 主方式

| 状態 | 主方式 | 合計に使う値 |
| --- | --- | --- |
| 類似し、工程と規模指標が対応する実績が3件以上 | historical | 実績の単位工数 × 対象規模のPERT |
| 上記未満で、算定できるWBSがある | cold-start | WBSの三点見積もり。必要な独立予備だけ加算 |
| どちらも無い | 未算定 | 数値を作らない。不足事項を返す |

3件、類似度0.60、工程Jaccard 0.50は、このツールの方針である。IPAやCoBRA法の規定値として説明しない。CoBRA法は実装していない。

## 補助

- historical が主方式でWBSもある: WBSは照合用。加算しない。
- cold-start が主方式で按分できる実績が1件以上ある: 実績見積もりは補助。加算しない。
- 類似度が下限未満の実績: 不採用理由を書き、係数補正しない。

## 上書き

`method_override` に `cold-start` を指定すると、実績が十分でもWBSを主方式にする。`historical` は按分条件を満たすときだけ指定できる。

## 実績が一部だけ使えるとき

冷スタートを主方式にし、使える実績は類似案件として併記する。規模指標が違う実績から工数を比例配分しない。
