# ケースA: 過去実績がない新規Webアプリ

## 入力

架空の社内タスク管理Web。ログイン、タスクの登録・更新・完了、一覧の絞り込み。同時利用は約20名、社内HTTPS。モバイルアプリ、データ移行、新規インフラ、CI/CDは対象外。社員マスタの有無は未確定。過去実績は無い。

SLOCが無い状態でIPAの新規開発SLOC生産性を照合依頼に含め、不採用になることを確認する。

## 期待結果

- 主方式は cold-start
- 計画工数はWBSのPERT合計
- 単価と人数があるため、費用は算定され、期間は確定値ではない下限
- ベンチマークは `not_applied`
- 根拠区分は AI_ESTIMATE

## 検証観点

- 実績が無くても見積もりが中断しない
- UI、API、DB、認証、テスト、レビュー、不具合修正、管理が追跡できる
- IPAの統計を、条件不一致のまま計画工数へ入れない
- 費用と期間が工数と別項目である
